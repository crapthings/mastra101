# 第十七章写作指南：评估

## 章目标

承接 16：执行顺利仍可能交付错误结果。读者能从后续 Agent 的使用要求定义标准，组合规则与模型评分，保存版本化样本，以批量、门槛、在线和实验机制检查改动。

## 节目标与段落推进

| 节 | 节目标 | 段落推进 |
| --- | --- | --- |
| 评估标准（Evaluation Criteria） | 从实际交付要求定义可检查的标准 | 追踪未解决内容正确 → 通知用途 → 允许/禁止结果 → 分数语义 → 规则检查 |
| 规则检查（Quick Checks） | 理解确定性检查的适用范围 | 明确条件 → 下载运行 → 相反表述都命中 → 工具检查边界 → 结构化字段 |
| 自定义评分器（createScorer） | 以明确规则返回分数、理由或无法评分 | 字段协议 → 可选阶段 → 原生实现 → groundTruth/输入依据 → 不可评分 → 语义判断 |
| 模型评分（LLM as a Judge） | 用模型判断语义并人工校准 | 同义表达 → 人维护标准 → 提示对象与 Schema → 校准/注入/偏差 → 固定测量方式 |
| 数据集（Datasets） | 将反例变成有版本的回归样本 | 问题留档 → 覆盖范围 → 输入/参考分离 → 存储与版本 → 分页 → 复现条件 |
| 批量评估（runEvals） | 执行目标并解释逐条与平均分 | 现成输出评分 vs 执行目标 → 注册与存储 → 样本/并发 → 2/3 原因 → 放行问题 |
| 门槛与判定（Gates & Verdicts） | 区分硬性要求与平均分阈值 | 单条失败 → gate → coverage → threshold 方向 → 三种 verdict → CI 需明确策略 |
| 在线评分（Live Evaluations） | 收集事后信号并分清拦截责任 | 实际新样本 → 步骤参考资料 → 挂载/采样 → 异步落库 → 有限等待 → Guardrails 边界 |
| 版本实验（Experiments） | 固定样本/评分方式比较版本 | 固定条件 → 注册目标与 id → startExperiment → 运行计数 vs 质量 → Studio → 回归循环 |

章、节、段落目标仅用于编辑。本节检查要求读者决定结果是否能交给后续 Agent，不考字段背诵。

## 示例与边界

- Node.js >=24；固定 core 1.80.0、evals 1.10.9、libsql 1.27.1、zod 4.6.7。
- 十一个源文件：三辅助模块，02—09 八个入口。JS/TS 与 ZIP 同步，六份元数据，不包含 node_modules、真实 .env 或数据库。
- 只有 04 调用 vercel/openai/gpt-6.1-sol，使用 AI_GATEWAY_API_KEY。其余都是实际框架 API 执行的固定规则/工作流，不冒充模型表现。
- Quick Checks 接受 Agent 消息格式；不把普通 Workflow 输出直接传进去。示例清楚说明人工保存回答。
- 自定义评分只判定状态、入口、来源，不声称覆盖全部语义。缺少参考用 notScorable；业务的“入口未公布”本身是可评样本，不混同无法评分。
- 模型 Judge 的 analyze 用提示对象真正触发模型，程序映射分数并复用理由。函数步骤不会因为配置 judge 就自动请求模型。
- runEvals 从实例获取注册目标，评分器同样注册以保证保存。data 的 groundTruth 不交给目标。concurrency=1 用于容易观察。
- Gate 以可评分样本平均 1 为要求；threshold 比较均分，支持方向；verdict 缺省与证据不足需要单独处理，不能视为 passed。
- 步骤在线评分采样率 1，在后台执行。工作流返回后查询 scores 域，以 runId 关联并有限等待；不伪造同步阻断。
- LibSQL 内存存储独立脚本退出清空；不宣称这些运行自动出现在另一个 Studio 进程。正文区分持久存储后的 Studio 功能与本实验。
- 数据集版本通过真实修改产生，按 version/page/perPage 查询旧版本。实验固定版本，targetId 用工作流 id，scorers 用评分器 id。
- completed/succeededCount 描述执行；质量看逐条 scores。区分 runEvals verdict 与实验状态。

## 验证要求

实际运行无模型入口，确认 Quick Check 两条均 1、自定义 1/0/无法评分、数据集版本递增、批量均分 2/3、三种判定、在线结果 1、实验旧版有 0 而新版全 1。

模型评分仅替换为本地 V2 流式响应，保留真实 createScorer analyze 流程，阻断远程请求。此验证不代表真实评审模型判断准确或网关权限可用。

不运行 pnpm build/lint/test，不启动 dev；用源码解析、SSR、链接/资源/代码一致性与实际 Node 24 示例运行检查。SSR 不等于浏览器交互测试。

## 最终复核

JS/TS 各七个无模型入口全部通过断言：两次关键词检查均 1，字段评分 1/0/无法评分，数据版本递增，旧版本均分 2/3，failed/scored/passed 三种判定，在线步骤评分 1，旧实验包含 0 分而新实验全 1。另验证 runEvals 三条评分确实写入 scores 域，残缺参考资料不会误判满分。模型评审入口各通过一次本地 V2 流式固定响应验证，远端 fetch 阻断。

目录共 17 章 145 节；22 份 JS/TS 正文源码引用匹配，453 个源码解析和 9 种高亮语法加载通过。290 个语言版本页面、66 个图示 SSR 通过，三张新增 SVG 已视觉检查。每个 ZIP 的 17 个文件逐字匹配原文件，未包含依赖、凭证或数据库。

## 本轮 polish

- 用途 → 依据标准 → 字段检查 → 语义判断的推进更集中，明确本章验证输出与通知一致，通知的真实性和时效仍需查询与校验保证。
- 统一“基线版 / 修改版”；补清模型评审可以使用相同或不同模型，无需强制另选模型。
- 明确“入口未公布”仍是可评分的业务状态，与拿不到参考资料区分；九道检查题以具体判断和后续使用为主。
- Gate 用 99 条得 1、一条无法评分的例子解释覆盖范围；保留 scored 与 verdict 缺省的实际语义。
- 在线评分强调异步并发完成，不承诺先业务返回后才开始评分；事后监测与执行前控制分别说明。
- 数据集入口额外打印旧、新版本的审核标记，展示实际版本差异；评分与工作流逻辑未改。
- 精简内存存储、发布提醒等重复文案；图中逐一标注三个可选阶段与 generateScore 必需，同步图示称呼。
