# 第十一章写作指南：技能

## 章目标

把任务方法从通用系统提示词中分离，能定义、发现、加载与核对技能，理解“已配置”“已加载”“已遵循”是不同证据。

## 节目标与段落推进

章、节、段落目标只用于内部写作；正文通过现实任务的需求自然引出下一项机制。

| 节 | 节目标 | 段落推进 |
| --- | --- | --- |
| 技能与职责（Skills & Instructions） | 把具体任务的方法单独维护，让助手按需使用，而不是不断加长通用提示词。 | 同一个助手，做三件事有三套方法 → 职责、方法与执行分别放在哪里 → 先配置一个最小技能 → 规则要能用结果检查 |
| 技能定义（Skill Definition） | 给方法一个稳定名称，用简短描述说明何时使用，再用正文写清怎样处理。 | 先让人和模型知道何时需要它 → 把规则写成可观察的动作 → 校验名称与技能文件结构 → 定义好以后，还要知道怎样加载 |
| 发现与加载（Discovery & Loading） | 按用途发现技能，逐步读取规则，并用运行记录核对本次是否实际加载。 | 先看用途，再读具体方法 → 三个技能工具各做什么 → 用工具记录确认加载动作 → 加载成功以后，继续检查结果 |
| 技能文件（SKILL.md） | 把任务方法组织成可阅读的文件，理解目录、元数据与正文各自的作用。 | 方法稳定以后，可以像资料一样维护 → 先看随包提供的技能原文 → 文件技能可以直接挂到 Agent → 文件里写了方法，也需要可用资料 |
| 参考资料与模板（References & Assets） | 把细节留在支持文件中，需要时读取，并核对产物是否符合方法与资料。 | 入口写方法，细节放在支持材料 → 先列出文件，再明确读取内容 → 模板决定形式，资料决定依据 → 不同任务，可以提供不同的方法集合 |
| 动态技能（Dynamic Skills） | 让应用条件决定可用方法，分清技能范围与实际操作权限。 | 同一个 Agent，也会服务不同任务 → 用独立请求上下文观察两份目录 → 提供方法，不等于批准动作 → 最后用同一组资料核对改动 |
| 技能核对（Skill Verification） | 沿选择、读取与交付检查方法是否真正帮助任务完成。 | 先提出能用结果回答的问题 → 用两组资料对照同一种方法 → 定位偏差，再修改相应环节 → 下一步给方法提供真实的材料位置 |

## 边界

Agent.instructions 负责通用职责；createSkill.instructions 是按需加载的方法内容，不自动成为系统提示词、程序步骤或用户授权。文件结构校验不保证规则有效。参考资料与模板按需读取，scripts 需要另行执行。动态技能按请求解析，不把请求字段当作认证。
