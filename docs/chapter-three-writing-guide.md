# 第三章写作指南：快速开始

六节正文构成一条连续实践。目标是跑通固定示例，核心组件细节留给 04。

## 章目标

读者能准备独立练习项目，运行 Mastra Agent，接入真实时间工具，核对调用记录，并区分接入失败、工具业务失败与任务未完成。

## 本轮打磨

- 供应商说明先给出固定 Vercel 配置，再讲厂牌、API/SDK 与路由关系；其他云平台及网关只作简短概念补充，不展示替代操作路径。
- 固定使用 `vercel/openai/gpt-6.1-sol` 与 `AI_GATEWAY_API_KEY`，其他渠道只作理解接入方式的对照，不引出选型讨论。
- 首次调用及最终查询采用“先运行、再读文件”的顺序，环境准备明确下载包已包含完整项目。
- 在时间函数、模型记录、最终回答三个层面分别说明观察依据，减少重复的否定式提醒。
- 将失败处理整理成定位表和三个完成标准；明确 `.env` 缺失可能在脚本启动前报错。
- 以完整文件块对照源代码，不展示未经执行却标作真实结果的模型回答。

## 成果与边界

- 一个时间查询助手，输入为明确时区标识；本章不处理城市到时区的匹配。
- 运行环境的系统时钟是数据来源，两个时间字段表示同一取样时刻。
- Node.js >=24；默认 JavaScript，可切换 TypeScript；固定直接依赖并附带各自的 pnpm 锁文件。
- 不启动网站服务、不真实预订、不接入记忆或工作流，不展开高级路由策略。
- 每次运行是新任务，不暗示保存历史或长期偏好。
- 保留首次定义处的术语加粗；提示框用于结论和容易误解的边界，避免重复所有正文。

## 节目标与段落推进

每个编号对应正文小节，箭头表示内部自然段推进。

### 1. 接入模型服务

节目标：通过 Vercel AI Gateway 调用 GPT-6.1 Sol，准备本章唯一需要的模型配置和凭证。

1. 首先给出唯一运行配置 → 说明后续都沿用同一入口。
2. 区分厂牌、型号与接入服务 → 用 Grok 和云平台简短说明关系。
3. 解释 API → 说明 SDK 封装 API 请求 → 定位 Mastra 的调用层。
4. 拆解 Vercel 模型标识与请求路径 → 其他网关仅作名称补充。
5. 准备 AI_GATEWAY_API_KEY → 衔接 .env 加载和项目配置。

边界：不列其他入口的密钥表、替代 model 配置或 Cloudflare 请求体。保留厂牌与供应商概念，但所有可操作例子都指向 Vercel，不讲选型与模型适用任务。

### 2. 准备运行环境

节目标：准备独立练习项目，让第一次模型请求具备完整的运行条件。

1. 检查运行版本 → 明确解压后的工作目录和完整文件 → 说明语言切换与下载版本的关系。
2. 说明依赖职责 → 安装并复制环境文件。
3. 填写正确种类的凭证 → 说明环境变量实际加载方式。
4. 按三个命令定位入口 → 明确配置检查属于示例代码。

### 3. 发起模型调用

节目标：运行一个没有工具的 Agent，再看它为什么还不能完成实时查询。

1. 发起第一次请求 → 判断是否获得响应，不要求固定措辞。
2. 对照 Agent 配置 → 找到 generate 和结果读取的位置。
3. 区分启动、配置和接入错误 → 先排除阻断问题。
4. 以收到响应为前提继续 → 引出时钟能力的缺口。

### 4. 接入时间工具

节目标：把真实时间函数包装成工具，明确它的输入、成功结果和失败结果。

1. 固定输入范围 → 解释同一次取样的两个时间字段。
2. 直接运行函数 → 对照字段和时区差异。
3. 解释工具结构 → 区分结构检查与有效时区判断。
4. 将工具挂到 Agent → 引出真实调用核对。

### 5. 核对调用结果

节目标：查看模型请求、真实工具结果和最终回答，确认一次时间查询确实发生。

1. 运行最终入口 → 依次核对参数、结果和回答。
2. 读取 run.ts → 定位真实回调记录与最终文本。
3. 区分取样时刻和阅读时刻 → 以返回数据作为核对依据。
4. 识别任务未完成 → 引出可控失败。

### 6. 处理失败

节目标：用一个可控错误检查失败路径，完成本章小项目的验收。

1. 直接制造无效时区 → 再经模型观察实际参数。
2. 区分启动、接入与业务失败 → 说明 ok 是示例字段、失败结果不等于程序异常 → 用定位表找到检查位置。
3. 区分模型步数与时间限制 → 避免把停止当成成功。
4. 使用三个场景验收 → 留下一次 generate 的多步记录与 readTime 的工具包装两个问题，由 04 前两节接住。

- [Vercel GPT-6.1 Sol](https://vercel.com/ai-gateway/models/gpt-6.1-sol)：所选模型目录。
- 厂牌与云平台说明附官方链接；Vercel 接入与认证文档服务于本章唯一运行路径。

## 验证范围

TypeScript 源文件在 `examples/03-time-assistant`，JavaScript 版在 `examples/03-time-assistant-js`；各自对应 public/downloads 下同名 ZIP。

- 原示例使用真实依赖完成 Agent 创建、工具执行及输入输出结构检查；切换 Vercel 后没有发起真实网关模型请求。
- 本次复核时间函数的正常与无效时区、缺失与占位凭证、正文代码与源文件一致性、ZIP 完整性，以及课程数据和 JSX/TS 语法。
- 未使用真实密钥，未声明真实模型回答或完整 onStepFinish 行为已经验收。
- 未运行网站开发服务、构建或测试脚本。此次以内容与示例一致性为范围，没有进行新的浏览器视觉验收。

维护时先修改 TypeScript 源文件及对应正文，再运行 `python3 scripts/sync-example-variants.py` 同步 JS、两套正文代码和下载包；核对转换结果，不得包含 `.env` 或 `node_modules`。具体方案见 code-examples.md。
