# 第一章写作指南

本文只用于编辑，不作为课程正文展示。

## 章目标

读者能够解释模型如何产生回答、回答有哪些局限，以及为什么需要应用代码配合；理解工具调用和调用循环后，能够理解后续框架体系章节要解决的应用问题。

## 写作约定

- 目录及正文主标题采用简短的主题式名词短语，不混用问句、命令句和“介绍……”式标题。
- 节目标限定一个主要学习结果，用自然的副标题呈现；内部目标清单不直接展示。
- 每个自然段承担一个推进动作：提出事实或问题、解释机制、给出例子、限定边界或引向下一步。
- 段落之间用因果、条件或实例承接，不靠反复写“接下来”制造连贯。
- 一节结束时留下下一节要解决的问题；下一节开头接住这个问题。
- 示例围绕实际任务展开。绿色用于可记住的结论，红色用于误解和风险，避免重复正文。
- 技术术语只在首次定义或关键区分处使用 **加粗**；不自动匹配全篇、不反复加粗同一词、不高亮整段。代码保持原文，绿红色块继续用于结论与误解，不用于术语装饰。
- 中文优先独立写作。先把逻辑写顺，再考虑字数与翻译。

## 内容边界

- 训练只讲数据、预测、比较差距和调整参数，不展开算法术语。
- 消息只讲输入组织，API 接入、SDK 和 Gateway 留到实践。
- 上下文只讲相关前文和容量限制，摘要、检索及长期记忆策略后移。
- Agent 的命名、定义和框架抽象留到 Mastra 章节，第一章只描述调用循环。
- 工具和循环只建立执行认识，不讨论重试策略、并行调用或接口协议细节。
- 调用循环作为章末：简要说明程序检查请求、执行工具和控制停止，再引出跨会话任务的问题；状态、记忆和执行支撑在第二章建立认识。
- “普通推理不修改参数”在训练节完整解释，后文通过资料实例运用，不重复展开。
- 色块提炼结论或指出具体误解，不把同一句话改成正反两种表达重复上色。
- 练习只验证本节已讲的认识，不要求设计尚未介绍的机制。

## 节目标与段落推进

每个编号对应正文的一个小节，箭头表示其中自然段的承接。

### 1. 模型与权重

节目标：分清模型结构、权重和推理程序，认识模型运行所需的组成部分。

1. 从旅行回答引出模型 → 区分结构和参数。
2. 说明权重来源及作用 → 区分数值文件与原始资料。
3. 说明加载和推理 → 说明运行位置。
4. 归纳运行的前提 → 追问权重来源。

### 2. 训练与推理

节目标：从训练数据到模型权重，了解模型如何获得生成能力。

1. 承接权重来源 → 引入数据。
2. 展示预测任务 → 解释 Token。
3. 说明比较差距与调整参数 → 说明重复训练的结果。
4. 解释续写与问答的差别 → 引入后训练目的。
5. 区分推理与训练 → 引出应用如何组织消息。

### 3. 提示词与消息

节目标：把通用要求和当前任务组织成消息，理解它们如何共同影响回答。

1. 提出旅行需求 → 补充通用要求的必要性 → 定义提示词与消息的关系。
2. 展示通用要求 → 区分两种消息角色 → 对照代码。
3. 解释消息如何复用 → 对照需求检查结果。
4. 交代消息通过接口发送 → 引出追问所需的前文。

### 4. 上下文

节目标：理解多轮对话为什么依赖相关历史，以及上下文容量带来的限制。

1. 用追问引出前文 → 定义上下文。
2. 展示保存消息列表 → 解释助手回复的角色 → 用完整的消息示例呈现追问。
3. 说明容量限制 → 联系 Token 和模型限制。
4. 用出行条件说明信息选择 → 引出信息已提供仍可能遗漏。

### 5. 注意力

节目标：分清上下文中存在的信息与实际正确利用的信息，认识注意力机制，并对遗漏作分层排查。

1. 承接“杭州两天，带老人，少走路” → 用连续步行安排说明条件未落实，不能只检查是否复述条件。
2. 定义注意力为跨位置加权组合 → 区分人的专注、参数权重和消息优先级。
3. 上下文容量与有效利用不同 → 用长上下文研究说明表现依赖输入与任务，不推广为固定位置规律。
4. 先检查输入是否完整 → 再检查要求和结果，不凭最终输出归因内部注意力。
5. 组织信息后仍需核对 → 从漏写引向编造信息。

### 6. 模型幻觉

节目标：识别看似可信却缺乏依据的回答，学会对照资料核实关键内容。

1. 展示不存在的餐厅 → 说明提供上下文仍可能出错。
2. 定义幻觉 → 区分生成与核查。
3. 展示多推断一天的错误 → 说明逐条对照的方法。
4. 引入资料有效时间 → 用当前时间引出时效问题。

### 7. 知识的时效

节目标：用“现在几点”区分训练得到的知识与应用运行时提供的信息。

1. 提出当前时间问题 → 区分时间规则与当前时刻。
2. 说明参数不会随时钟更新 → 引出时刻和时区来源。
3. 说明应用提供时间的方式 → 区分答对和真实获取。
4. 扩展到其他实时数据 → 引出模型请求工具查询。

### 8. 工具调用

节目标：理解模型如何请求外部能力，以及程序如何执行工具并返回结果。

1. 承接读取时钟 → 扩展到餐厅查询工具 → 明确工具调用返回结构化请求。
2. 展示用户提问到工具结果回传的顺序。
3. 说明查询结果需要交回模型 → 解释结果成为新输入。
4. 展示查询后尚未完成任务 → 引出多次调用。

### 9. 调用循环

节目标：理解一次任务中的调用循环，以及模型和工具如何反复配合。

1. 展示后续查询需求 → 说明下一步依赖结果。
2. 说明结果回传 → 区分用户任务与模型调用次数。
3. 展示生成、执行、继续、结束的循环。
4. 区分完成与未完成时结束 → 归纳模型与程序的分工 → 引出下一次会话如何继续任务。


## 注意力伏笔的边界与依据

位置：上下文之后、模型幻觉之前。第一章共九节，不改变原有路径。

只介绍跨位置加权组合的直觉，不展开 Q/K/V、公式、注意力头数量、训练或源码实现。注意力权重不等于模型参数，也不等于消息角色优先级；模型输出不足以反推出单次注意力计算原因。

“Lost in the Middle”只作为特定研究中长上下文利用差异的依据，不推断所有当前模型都固定忽略中间内容，也不声称位置调整必然有效。后续提示词、记忆筛选与文档处理可以回扣“信息进入上下文不等于正确利用”，但不把所有遗漏都归因于注意力。
