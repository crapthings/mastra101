# 第九章写作指南：存储

## 章目标

承接 08 已经可运行的记忆配置，理解数据保存到哪里、配置影响谁、不同运行数据如何分工，并能直接读回记录验证持久化、领域路由和清理。

本章继续使用活动资料，但示例全部是本地存储操作，不通过模型复述判断数据是否保存。09 结束后再进入工作流，先具备理解运行快照落点的基础。

## 节目标与段落推进

| 节 | 节目标 | 段落推进 |
| --- | --- | --- |
| 存储与持久化（Storage & Persistence） | 区分存储接口与数据保留 | 退出后找资料 → 接口与后端 → 两进程读回 → 连接位置 → 配置范围 |
| 配置范围（Configuration Scope） | 核对共享与覆盖的落点 | 多助手 → 覆盖范围 → 双后端读回 → 数据范围 → 领域 |
| 存储领域（Storage Domains） | 按运行职责识别数据 | 消息与执行进度 → 常用领域 → getStore → 功能启用 → 适配器 |
| 存储适配器（Storage Adapters） | 确认进程连接的位置 | 适配器职责 → 绝对路径 → 后端需求 → 迁移边界 → 向量 |
| 原文与向量索引（Storage & Vector Index） | 把候选标识接回原文 | 向量与消息 → 同一消息标识 → 查询核对 → 拆分职责 |
| 组合存储（Composite Storage） | 把领域映射到具体后端 | 拆分动机 → default/domains → 读回证据 → 访问范围 → 保留时间 |
| 数据生命周期（Data Lifecycle） | 验证规则、执行和范围 | 增长 → retention/prune → 新旧记录 → 进度与磁盘 → 生命周期 → 工作流 |

## 边界与示例

Node.js >=24；examples/09-storage 与 examples/09-storage-ts。依赖固定为 @mastra/core 1.80.0、@mastra/memory 1.39.1、@mastra/libsql 1.27.1。七个独立入口，全部本地运行，不需要密钥。02 创建 Agent 只为说明实例继承与 Memory 局部覆盖，不调用 generate，保留统一模型字符串 vercel/openai/gpt-6.1-sol。

01 用两个独立进程读回固定教学会话。02 直接在两个后端检查记录落点。03 对照 Memory 便捷接口和存储领域接口，不展开工作流或评分器。04 打印绝对路径，不部署其他服务。05 用固定三维向量演示消息标识关联，不把它宣传成中文语义嵌入。06 用两个本地文件演示领域路由，不把配置变更说成数据库迁移。07 只清理专用教学文件中过期消息，不扩展成完整用户删除实现。

存储 id、连接位置、用户归属和会话标识分别解释；共享数据库不等于自动共享记忆。存储后端提供领域接口，也不等于工作流、追踪、评估自动启用。retention 声明规则，prune 执行工作，done 表示本轮进度；清理数据库行不等于磁盘文件马上缩小。

数据库迁移、备份系统、多机部署和完整生产运维不在本章展开；适配器一节提供选择问题和文档入口。接口名和技术词在首次关键出现处加粗，中文正文以当前教学任务承接，不堆平台名称。

## 验证

在新的临时目录运行七个原始 JS 入口；01 的写入与读取使用独立 Node 进程。验证进程禁止 fetch，所有操作均为本地数据库读写，没有远程服务。

实际读回结果：02 的共享记录在共享后端、独立记录仅在独立后端；03 可以取得 memory/workflows/scores，并能保存与读取会话；04 文件 URL 连接成功；05 查询元数据能关联回东门入场原文；06 覆盖领域包含新记录，默认 memory 没有该记录，workflows 使用默认接口；07 两条消息清理后剩一条，删除数为一且 done 为 true，会话仍存在。

不运行 pnpm dev/build/lint/test；语法和下载资源使用独立检查验证。正文只声明这些本地结果，不声称已经验证跨服务部署或生产清理策略。

最终一致性检查：全书 82 节标题、懒加载路由和前后导航一致；09 七节 JS/TS 文案、代码块、命令、三个图示挂载及两个各 12 文件的下载包与源文件一致。147 个相关源文件通过语法解析，diff 无空白错误。七个原始入口在禁止外部 fetch 的临时进程中完成上述结果断言。当前工作尚未提交或发布。
