# 第二十章写作指南：部署与运行

## 章目标

把 18 的服务接口、19 的认证、09 的存储、16 的观测与 17 的评估连成可交付应用。读者能区分代码、环境、进程与持久数据，按实际证据检查启动、运行、停止与版本切换。采用一条贯穿的 Node 24 适配器路径，兼具 JS/TS 源码、容器文件和可运行验证。

## 实现与依赖

- Node.js >=24；五源文件（config/application/runtime/main/verify）、八元数据（含 Dockerfile/.dockerignore），JS/TS 各一份。
- core 1.80.0、hono adapter 1.7.22、libsql 1.27.1、observability 1.22.0、duckdb 1.16.0、node-server 1.19.11、hono framework 4.13.13、zod 4.6.7，pnpm 12.4.1。
- 采用 Node 直接运行适配器，不安装 CLI、不实际运行 mastra build；正文解释另一条交付路径但不混入本例命令。
- API 令牌从环境注入并校验长度；模型另需 AI_GATEWAY_API_KEY，但所有验证只运行固定工作流，不请求付费模型。
- LibSQL 保存 application.db，DuckDB 保存 observability.duckdb；单进程本地文件模式。生产多副本需要合适共享存储，不宣称共享 DuckDB 文件是分布式方案。
- 启动先验证配置、创建目录、初始化存储，再监听与 startWorkers，最后 ready。探针有限状态；ready 表示本例启动条件，不承诺依赖持续正常。
- Workers 使用默认进程内模式，没有配置分布式 PubSub、调度或外部 Runner；工作流历史持久化不等于自动恢复所有在途操作。说明调度器与队列的职责和扩容范围。
- 关闭先撤下 ready，http.close 停接新连接并等待在途；HTTP 超时强关，随后 mastra.shutdown 排空与导出/存储关闭。HTTP 和框架各用一次 SHUTDOWN_MS，不能承诺整个进程总共仅此预算。
- verify 启动独立子进程，查询到长请求 running 后才 SIGTERM，等待其结果与退出码；用同目录启动 release-b 读回旧 runId 与追踪。临时凭证和目录最终清理。
- Docker 在 Linux 镜像内安装依赖，以 node 用户运行；数据卷承接 /app/data。不可将 macOS node_modules 或环境文件打包进镜像。
- 同步脚本增加 Dockerfile/.dockerignore 可选元数据、TS Docker 入口替换；扩展名替换使用精确 .js 边界，避免误改 package.json，继续保留 Node.js 名称。Dockerfile 语法按需加载，不扩大入口包。
