# 第十二章写作指南：工作区

## 章目标

组织 Agent 使用的文件、检索与技能资料，能区分路径范围、请求归属、索引更新和产物持久化。

## 节目标与段落推进

章、节、段落目标只用于内部写作；正文通过现实任务的需求自然引出下一项机制。

| 节 | 节目标 | 段落推进 |
| --- | --- | --- |
| 工作区配置（Workspace） | 把文件、搜索与共享方法组织到一个明确的工作范围，先让资料有处可读、产物有处可放。 | 方法写好了，资料放在哪里 → Workspace 组织能力，Filesystem 落实文件操作 → 先读回一份活动资料 → 文件与运行数据各自有位置 |
| 文件系统与路径（Filesystem & Paths） | 区分文件接口里的相对路径、宿主绝对路径与配置根，核对实际读到哪份材料。 | 一个路径，需要放到它的接口里理解 → 用两种写法读取同一文件 → 多个文件来源，还需要明确挂载前缀 → 路径选对以后，再考虑怎样改文件 |
| 文件读写（File Operations） | 把读取、覆盖和只读限制落实到具体文件，核对当前内容而不是只看成功提示。 | 读到了旧内容，写入才有明确依据 → 观察一次覆盖与一次被拒绝的写入 → 只读接口与命令权限分开 → 材料变多以后，需要找到相关片段 |
| 搜索与索引（Search & Indexing） | 从资料中找候选片段，并让索引随原文更新，保留来源与时间依据。 | 文件在，不等于索引已经包含新内容 → 显式写文件，也显式更新索引 → 候选片段还需要回到任务里核对 → 资料可搜索，方法也可以共享 |
| 技能目录（Workspace Skills） | 把技能发现接到文件系统，分清项目共享方法与单个 Agent 的覆盖。 | 同一份方法，可以供多个助手使用 → 先准备文件，再开始发现 → 先核对解析结果，再核对任务行为 → 共享方法之外，用户资料还要分开 |
| 资料范围（Resource Scope） | 按应用确认的归属选择文件位置，避免把共享工作区误当成自动按用户隔离。 | 同一个助手，可以读取不同用户的材料 → 先确认标识，再解析文件系统 → 目录范围与访问授权分别落实 → 资料范围明确之后，保留交付物 |
| 产物与持久化（Artifacts & Persistence） | 让生成结果有明确位置和内容依据，区分文件保留、用户确认与运行记录。 | 一段回答之外，还需要可用的文件 → 退出后再读取，核对文件和摘要 → 回收对象与删除文件分别判断 → 下一步让程序真正处理材料 |

## 边界

LocalFilesystem 的 basePath 限制相应文件接口；绝对路径仍是宿主路径，不能把 /docs 当作虚拟根目录。readOnly 不等于操作系统隔离。写入文件不会自动更新已建索引；同名 Agent 技能可覆盖其解析结果，但不改写源文件。资料范围必须结合可信身份建立，示例白名单不是认证。Workspace 不要求配置 Sandbox。
