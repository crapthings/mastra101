# 第十四章写作指南：子智能体

## 章目标

承接沙箱带来的执行能力，在活动资料核对与提醒文案中学习任务委派。读者能按职责拆分 Agent，控制子任务输入与结果范围，分别管理父子预算、取消与会话，再沿实际记录检查协作是否有效。

章、节、段落目标保留在内部指南。正文从任务中的新需求推进，不把写作结构或机器验收清单写成读者内容。

## 节目标与段落推进

| 节 | 节目标 | 段落推进 |
| --- | --- | --- |
| 子智能体配置（Subagents） | 理解父子运行与工具、技能、工作流的区别 | 执行能力已具备 → 职责开始分化 → agents 注册 → 一次委派的两层运行 → 用途说明 |
| 委派说明（Description） | 按调用方与执行方分别维护描述与规则 | 任务视角不同 → description/instructions/prompt 分工 → 配置目录 → 职责与材料衔接 |
| 上下文传递（Message Filtering） | 控制消息历史与委派提示两条内容路线 | 父历史默认可转发 → 历史与 prompt 分开 → 请求数据浅复制 → 受控输入 → 结果返回 |
| 结果交接（Result Context） | 区分模型可见结果与应用原始结果 | 查询与总结 → 默认文本交接 → 原始数据与完整开关 → 定位交接偏差 |
| 委派控制（Delegation Hooks） | 分别处理拒绝、执行失败与钩子故障 | 委派前检查 → 完成后处理 → 钩子错误策略 → 三种模式 → 运行预算 |
| 运行预算（Budgets & Cancellation） | 按父子运行分别限制步骤并传递取消 | 父步骤容纳子循环 → 查询与整理预算 → 模型参数上限与程序覆盖 → 取消传播 → 审批边界 |
| 会话与记忆（Memory Isolation） | 分别核对看到的背景与保存的消息 | 可见与保存分开 → 同后端不同会话 → 两次实际委派回查 → 共享与权限边界 |
| 协作核对（Delegation Verification） | 检查两阶段交接及事实忠实度 | 核对后写提醒 → 结果引用 → 程序阶段检查 → 正常/缺失/失败 → 后续扩展 |

## 核心边界

- agents 对象键 reviewer 生成 agent-reviewer；Agent id activity-reviewer 用于 primitiveId 等身份字段。两处名称分别讲清。
- 子任务配置独立，不表示输入天然只包含新 prompt。父上下文先整理工具部分再转发；messageFilter 控制历史，modifiedPrompt 处理本次委派任务。两者不能互相替代。
- RequestContext 条目浅复制不等于嵌套数据深复制；模型可见仍由这些值如何进入消息、指令或工具结果决定。
- 默认子文本进入父模型，应用仍可查看嵌套工具结果与子会话标识；完整交接选项扩大模型可见范围，不提高事实可靠性。
- 拒绝、子任务执行错误、钩子故障分开。hookErrorStrategy: throw 让委派失败，不保证父运行也直接抛出；开始钩子错误可能不经过完成钩子。bail、resultText、feedback 的时机与作用分别介绍。
- 父 maxSteps 不计入全部子模型请求。主模型提出的子预算受子默认上限约束，应用 modifiedMaxSteps 在约束之后覆盖；取消信号传播也不等于撤销外部动作。
- 新委派使用新子 thread，转发背景与子会话保存的任务/自身消息分开。资源范围记忆仍需另查，线程划分不代替用户授权或系统隔离。
- 结果引用仅在当前父运行内有效，未知引用可能被跳过；阶段存在、文本存在与事实正确分别核对。固定业务顺序仍由工作流落实。
