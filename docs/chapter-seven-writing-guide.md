# 第七章写作指南：智能体

## 章目标

深入 Mastra Agent：把任务、配置、上下文和执行结果连接起来，能判断一次运行为什么继续、如何结束，以及结果能否供后续程序使用。

03 已跑通模型与时间工具；04 已解释组件职责；05、06 已建立提示词与模态知识。07 用活动资料助手持续推进，重点是 Agent 的实际运行，不重复概念目录，也不把全部产品扩展塞进一章。

## 节目标与段落推进

| 节 | 节目标 | 段落推进 |
| --- | --- | --- |
| 智能体配置（Agent） | 区分通用要求、本次材料与执行结果 | 结果用途 → 配置职责 → 发起任务 → 核对依据 → 调用设置 |
| 模型调用设置（modelSettings） | 区分模型、生成预算与运行设置 | 作用层次 → 常见参数 → 默认与覆盖 → 观察结果 → 请求条件 |
| 请求上下文（RequestContext） | 区分消息、应用配置与记忆 | 展示偏好 → 三类上下文 → 动态指令 → 历史与隔离 → 查询工具 |
| 工具调用（Tool Calling） | 理解工具结果如何进入后续调用 | 信息缺口 → 工具约定 → 调用步骤 → 三种业务状态 → 停止与完成 → 运行控制 |
| 运行控制 | 区分步数、取消、暂停与成功 | 步骤含义 → maxSteps 的 1/2/3 对照 → 预算选择 → 每步控制 → 自定义停止 → 信号传递 → 停止原因 → 结果交付 |
| 结构化输出（Structured Output） | 提供可供程序读取的交接对象 | 后续用途 → 两层 Schema → 生成对象 → 执行、结构与事实检查 → 兼容与失败 → 流式需求 |
| 流式输出（Streaming） | 区分进度与最终交付 | 部分文字 → 文本与事件 → 消费流 → 中断与提交 → 处理器 |
| 处理器（Processors） | 选择检查的介入位置 | 确定性检查 → 处理位置 → 消息 parts → tripwire → 检查器边界 → 防护策略 |
| 防护规则（Guardrails） | 区分违规处理与检查器错误 | 检查目的 → 内置能力 → 两类策略 → 注入示例 → 执行边界 → 失败恢复 |
| 错误处理与恢复 | 按失败层次安排恢复 | 失败分类 → 重试预算 → 每步反馈 → 外部状态核实 → 人工决定 |
| 工具审批（Tool Approval） | 将批准与实际执行分开 | 具体动作 → 快照与存储 → 用户决定 → 恢复后核对 → 与运行中暂停区分 |
| 代码模式（Code Mode） | 理解 Code Mode 的适用点与边界 | 多查询统计 → 编排与宿主工具 → 固定数据 → 运行环境与业务职责 → 整体复盘 |
| 运行记录与评估 | 根据证据定位问题并比较改动 | 保留证据 → 三条路径 → 定位与修改 → 追踪与评估 → 交付要求 |

所有十三节已写入两级目录，并通过独立路由懒加载。不存在待补充页面。正文只用自然问题承接，不直接展示内部目标。

## 示例约定

独立项目为 examples/07-agents（JS）和 examples/07-agents-ts（TS），分别有 ZIP 下载。Node.js >=24，模型统一为 vercel/openai/gpt-6.1-sol，凭证为 AI_GATEWAY_API_KEY。

每节入口分别是 src/01-responsibility 到 src/13-review。reservation 提供复用的只读教学工具。示例不是对真实报名系统的接入，不访问真实个人记录。模型请求会经过网关；本次编写与验收没有发起真实模型请求。

版本固定：@mastra/core 1.80.0、@mastra/libsql 1.27.1、@mastra/quickjs 0.1.5、zod 4.6.7。锁文件随包提供；JS/TS 使用相同执行逻辑，仅文件扩展名与本地导入路径不同。由 scripts/sync-agent-examples.py 同步源文件、正文代码块、语言变体与下载包，打包白名单排除密钥、数据库、草稿和依赖。

审批入口写本地草稿，必须由终端明确输入“确认”；其他输入拒绝。存储暂停快照不等于配置记忆，不宣传仅有数据库就实现跨进程恢复。

Code Mode 使用 QuickJS WebAssembly 运行编排代码，仅暴露两个只读教学工具。工具仍由宿主执行。桥接函数名以生成的 instructions 为准；工具 id 的连字符可能被规范化为下划线。不能直接假设工具变量名就是桥接函数名。

## 本节检查

每节以当前活动助手情境为依据，要求判断一项具体偏差：超出材料、错误解释业务失败、结构正确但事实错误、部分流被当作完成、请求配置被当作历史、处理器被当作权限、停止被当作成功、批准被当作执行、沙箱被当作工具授权、改动缺少对照依据。

不以记住 API 名称代替理解，也不要求读者实现尚未介绍的部署系统。

## 范围

对话消息与 Memory、Agent 与 Workflow、工具与其他 Agent 的连接处会交代；深入记忆、工作流、多智能体、渠道与部署留给后续。Studio 作为观察入口简述，终端记录不被称为已经配置的 tracing。

Guardrails 包含确定性或模型辅助检查，不承诺绝对安全；输出结束时拦截无法收回已流式展示的文字。输入 processors 不替代工具执行前的身份、权限与业务校验。

## 关键配置与源码目的

Agent 配置之后新增模型调用设置，调用参数按职责组织，不拆成单参数小节。tools / activeTools / toolChoice 位于工具调用；prepareStep / maxSteps / stopWhen / abortSignal 位于运行控制。源码的 PrepareStepProcessor 将 prepareStep 接到 processInputStep；它不是另一套调用循环。

错误恢复分别说明模型请求重试、处理器反馈重试与外部业务操作恢复。每步反馈示例使用 processOutputStep，不能换成整次结束后的 processOutputResult。maxSteps 不是所有请求和重试的总预算；总时间预算与各层重试上限分别配置。

本轮离线验证：默认输出预算 600 被本次 128 覆盖，下一次仍保持默认；prepareStep 首步指定查询、后续 none；stopWhen 在已有工具结果后停止；检测器故障 strict 不调用主模型、warn 继续；模型可重试故障按显式上限恢复；实际恢复示例在一次处理器重试后返回 tripwire。全部使用固定本地模型，不把它当成远程模型效果验证。

## 中英文术语标题

07 的核心概念采用“中文（英文术语）”，目录与正文主标题一致。英文保留官方概念或实际 API 的拼写，例如 RequestContext、modelSettings。运行控制、错误处理与恢复、运行记录与评估是组合教学主题，保留中文，不将直译包装为独立接口，也不把运行记录等同于 Tracing。

maxSteps 是运行控制的主线：先明确一次模型调用及其工具执行属于同一步，再说明下一步读取工具结果。区分步骤数、工具调用数、重试与 Token 预算；以 1/2/3 步对照帮助读者观察，不承诺提高上限即可完成任务。prepareStep 的源码关联放在处理器小节，避免提前展开实现术语。
