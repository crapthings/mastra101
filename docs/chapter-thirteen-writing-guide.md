# 第十三章写作指南：沙箱

## 章目标

理解代码运行位置、结果、依赖、进程、隔离和回收责任，让 Agent 能根据实际执行证据使用产物。

## 节目标与段落推进

章、节、段落目标只用于内部写作；正文通过现实任务的需求自然引出下一项机制。

| 节 | 节目标 | 段落推进 |
| --- | --- | --- |
| 执行环境（Sandbox） | 让程序在明确的位置运行命令，并按实际后端理解执行与隔离能力。 | 能读资料以后，还需要真正运行程序 → 先认清 LocalSandbox 的执行位置 → 启动后执行一个固定命令 → 下一步从执行结果判断发生了什么 |
| 命令与结果（Commands & Results） | 区分命令成功、部分输出与失败原因，用真实执行信息决定下一步。 | 日志能说明进度，退出码说明执行结局 → 比较正常完成与显式失败 → 程序启动失败与业务检查失败不同 → 继续检查命令运行时看到的环境 |
| 工作目录与依赖（Environment & Dependencies） | 核对脚本读取文件的位置、实际使用的运行时，以及需要准备的依赖。 | 相对文件路径从命令目录开始 → 让程序打印它实际收到什么 → 能运行 Node，不等于依赖都齐全 → 环境清楚以后，再处理一份真实形状的数据 |
| 代码与产物（Code & Artifacts） | 让代码完成确定性处理，再用原始数据核对输出文件。 | 统计工作交给代码执行 → 先看命令结果，再读回文件 → 生成方式与执行方式分开 → 处理时间变长后，需要控制进程 |
| 进程与超时（Processes & Timeouts） | 为命令设置等待范围，并明确管理持续运行的进程。 | 等待时间与业务完成条件不同 → 比较命令超时与后台进程回收 → 后台进程需要自己的结束安排 → 控制进程之外，还要控制它能做什么 |
| 隔离边界（Isolation Boundaries） | 显式选择隔离后端，验证具体策略，并保留平台差异与未覆盖范围。 | 目录、工具限制与系统隔离分别看 → 先检测能力，再运行受控场景 → 可启动，不代表策略覆盖所有访问 → 边界明确以后，还要安排复用与回收 |
| 生命周期（Lifecycle） | 明确环境的创建、共享和销毁责任，同时单独核对文件的保留。 | 静态环境与按请求解析，复用范围不同 → 同一用户复用，不同用户分开 → 进程结束与文件消失，也要分别核对 → 把方法、材料与执行连成一条任务 |

## 边界

LocalSandbox 默认使用宿主权限，工作目录不能代替权限隔离。命令退出成功与业务结果正确分开。超时、终止和产物核对分别处理；原生隔离检测、启动和某项策略生效是不同证据。固定版本 macOS 策略允许文件读取与临时目录写入，不宣传为工作目录封闭隔离。resolver 实例由应用安排回收，清除缓存与销毁实例分别完成；本地文件保留不能推广到远程后端。
