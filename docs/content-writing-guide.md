# 正文与本节检查的统一准则

## 面向读者的推进

每章解决一个阶段的问题，每节回答其中一个具体问题。段落先给当前情境，再说明概念与判断方法，最后由尚未解决的问题引出后文。章目标、节目标和段落目标留在写作指南，不直接写成正文提示语。

使用自然中文与真实任务形态；教学例子必须明确哪些材料为作者编写，哪些结果经过实际运行。技术名词在首次解释或承担关键含义时加粗，不把整段话都强调。绿色用于可迁移的结论，红色用于容易误判的边界，避免重复正文和相邻提示框。

## 本节检查

统一使用“本节检查”标题。题目应能根据本节与前文回答，使用已有场景，要求读者作出区分、修改或核对，而不是只寻找关键词。通常一至两个相互承接的问题即可，不为保持形式一致给所有题目硬加 Agent。

| 章 | 检查目标 | 不提前要求的内容 |
| --- | --- | --- |
| 01 大语言模型 | 分清参数、输入、依据、工具结果与调用循环 | 不要求搭建项目或掌握 Agent 框架 |
| 02 框架体系 | 判断状态、记忆、流程与运行支撑各解决什么问题 | 不背接口名称，不把框架当成唯一方案 |
| 03 快速开始 | 从实际调用记录判断路径是否接通、工具是否执行、结果是否可靠 | 不把配置复述、脚本退出或答案流畅当成验收 |
| 04 核心组件 | 区分配置、数据流、作用范围与执行控制 | 不提前扩成完整生产项目 |
| 05 提示词 | 写清任务与规则，用可观察结果决定是否保留改动 | 不以长模板、标签数量或模型自评代替证据 |
| 06 模态 | 判断不同输出如何供 Agent 使用，保留来源、条件与失败状态 | 不把每项练习变成部署、模型选型或完整控制系统设计 |
| 07 智能体 | 沿输入、模型步骤、工具与交付定位问题 | 不以步数、结构或批准代替完成状态 |
| 08 记忆 | 区分保存、取回、使用，以及会话与归属 | 不把记忆范围当作权限或系统隔离 |
| 09 存储 | 核对数据位置、配置范围、领域路由和清理结果 | 不把换连接当成迁移，或把单表删除当成全面清除 |
| 10 工作流 | 看清步骤依赖、数据交接、等待恢复与重试 | 不把技术结束状态当成业务完成 |
| 11 技能 | 观察方法怎样被发现、加载与应用 | 不把说明文字当作强制流程或授权 |
| 12 工作区 | 核对文件路径、内容、索引与产物 | 不把文件接口范围推广成命令权限 |
| 13 沙箱 | 核对实际执行、产物、进程、隔离与回收 | 不把工作目录或类名当成隔离证据 |
| 14 子智能体 | 核对委派输入、子结果、父回答与保存范围 | 不把子任务拆分当成天然隔离或固定顺序保证 |
| 15 外部连接 | 核对协议发现、服务执行、凭证范围与远端任务状态 | 不把统一调用接口当成运行时或权限自动互通 |
| 16 追踪与指标 | 从统计变化回到一次执行，按追踪与日志定位证据 | 不把运行成功当作内容正确，不把采样数据当作全量流量 |
| 17 评估 | 按实际用途建立标准，固定样本与评分方式比较结果 | 不把执行完成、均分或后台评分当成业务放行 |
| 18 服务接口 | 沿 HTTP 请求核对实际执行、响应、上下文与取消 | 不把接口连通、SDK 对象或客户端取消当成业务结果保证 |
| 19 身份与权限 | 根据认证身份、操作权限和记录范围判断实际访问 | 不把客户端身份字段、角色名或框架资源映射当成全部授权 |
| 20 部署与运行 | 验证启动、持久化、后台、停止与版本切换的真实结果 | 不把进程存活、卷存在或旧镜像当成业务可用与自动恢复 |
| 21 检索增强生成 | 沿原文、范围、候选与引用判断资料能否支持回答 | 不把相似、命中、重排分数或有效编号当成正确性保证 |
| 22 持续执行 | 区分连接、运行、目标、后台任务与恢复，核对结果能否继续使用 | 不把重连当重做、存储当自动恢复，或目标判定当真实授权 |

检查题中的正确做法必须在正文找到依据。开放题不要求唯一措辞，但要能说明检查的是哪种错误。配置问题应关联实际请求路径；输出问题应关联后续用途。
