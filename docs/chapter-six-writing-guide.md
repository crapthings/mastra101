# 第六章写作指南：模态

## 章目标

建立输入、理解、输出与生成的对应关系：先确认模型实际获得的材料，再检查事实与关系，最后按用途生成、检索或判断。专用模型和世界模型作为能力分工的扩展。

本章讲通用方法，用已核对的产品作具体例子；不要求读者安装前章项目。产品规格、示意数据与实测结果必须分清。

## 准确性边界

文档是可包含多模态内容的材料载体；PDF、Word 等文件格式不等于统一的输入能力。OCR、文字抽取、抽帧和转写都可能损失内容或结构。

通用讲解分别说明原始输入与转换路线，不推断任一具体模型具备所有能力。不提供伪造的模型响应，也不把教学稿说成真实识别结果。

只提供部分页面、画面或文字时，结论范围应相应受限。缺失、冲突和不确定性本身就是需要保留的结果。

## 文字与文档的衔接

文字节处理已提供内容的语义；结尾将同一内容保存为文件，引出读取环节。文档节先认识 TXT/MD、PDF、DOCX、XLSX、PPTX，再解释读取、抽取、整理与模型输入的关系，最后用原有活动摘录核对结构和语义。

“抽取后仍是文本”只适用于文本抽取路线，不概括所有文档处理。TXT 是解码读取；Office 文件需要解析其结构；表格要保留行列与单位；PDF 可提取文字、处理页面图像或经 OCR。页面图像属于另一类输入，不当成隐藏在纯文本中的信息。

以 https://developers.openai.com/api/docs/guides/file-inputs#how-it-works 为已核对的接口实例说明 PDF 文字加页面图像，以及非 PDF 文件的文字抽取差异。仅作反例，不将某个服务的具体处理方式推广为统一机制。正文无服务配置或调用代码。

此处未增加解析器或声称实际完成文件抽取，教学摘录仍明确由作者编写。


## 模型能力、内容与图像输入

“能力等级”拆成输入模态、上下文容量、图像细节处理与推理投入，不画成单一高低阶梯。上下文容量不保证有效利用；视觉细节设置不等同注意力强弱；推理强度影响计算预算，不自动改变模型架构、输入能力或窗口。

核心表述是实际提供的内容决定可用于理解材料的依据，不把所有模态都简化成纯文本。文字编码为 Token，其他模态有相应内部表示；更高投入不能补回未送入或转换丢失的内容。

图像节增加像素宽高、文件体积、清晰度、处理选项、多图关系、URL 与 Base64。传输方式不改变同一图像的细节，Base64 应作为图像数据按接口传递，不暗示模型会自动解码聊天框里的长字符串。多图不暗示任意数量可一次输入；不列随模型变化的固定限制。

依据：
- https://developers.openai.com/api/docs/guides/images-vision
- https://developers.openai.com/api/docs/guides/reasoning

仅作可核对的接口例证，正文保持通用原理，不绑定供应商或新增运行配置。


## 视频故事板

补充支持图像、不支持视频时的 4×4 网格故事板方法：选择 16 个时刻，按从左到右、从上到下排列，标注帧号与原视频时间。允许固定间隔或按变化取关键帧；不把 16 帧写成必需数量或保证覆盖全片。

以 2048×2048、每格 512×512 的纯尺寸计算说明拼图后的细节限制，明确尚未计入边框标签及服务端处理。这不是推荐的通用分辨率。网格仍是一张图片，不等于接口收到 16 个独立图像，也不假设模型按人工网格进行内部切分。

整板概览之后，按问题补清晰帧、局部图或时间片段。清晰度不足与时间采样不足分开处理；不暗示推理强度可以补回未提供的信息。原有三画面教学视频保留，用于最小顺序练习，没有伪装为 16 帧素材。

System One 为厂商类别命名，不写成已统一的行业分类。介绍其面向类型化判断的定位，不依据低延迟推断模型参数规模，不转述“零幻觉”或性能倍数为独立验证结论。例子为教学设计，未实际调用。

## 多模态模型的当前例子与证据

以 Gemini Omni 替换 Qwen2.5-Omni，正文按活动任务 → Gemini Omni 的多参考视频创作 → 输入输出组合表 → any-to-any 范围 → 产品与模型分工 → 检索需求推进。根据官方 Gemini Omni Flash 模型卡（含 1.1 Flash），输入为文字、图片、音频、视频，输出为带音频的视频。不能据此推断独立文字、图片、音频及全部组合均可输出。

不写“目前还没有真正的 any-to-any”这一全行业否定：NExT-GPT 原始论文已介绍基于语言模型、适配器与扩散解码器的多模态输入输出系统。保持研究系统、单个模型与开放接口的区别，不把可用性限制当成研究方向不存在的证据。没有实测 Gemini Omni。

## 输入与输出的正文呼应

输入入口先讲任务、实际收到的内容与理解含义，再讨论能力配置；读取转换图移到对应段落。输出入口承接已经核对的材料，先确定交付物，按文字、图像、声音、视频展开，与前半章顺序一致。

整体润色压缩重复的验证口号与产品发布口吻，保留具体检查动作、素材真实性说明和能力边界。既有路由、例子文件和图示数量不变，不新增产品能力断言。


## 多源信息核对的范围

该节专注来源、时间、适用对象与证据之间的关系，避免和多模态能力介绍重复。按同一事项 → 来源与时间 → 差异原因 → 确认、冲突、缺口 → 对外交付推进。区分活动日期与发布时间，不假设教学素材存在未给出的版本信息，不按数量投票判断事实。对照表依据已有海报、文档摘录与口语稿编写，不作为模型实测输出。


## 世界模型节的检查目标

本节检查转向“预测结果如何供 Agent 使用”，而非让读者验证模拟器或设计真实设备控制。要求识别输入条件、来源、模拟与实际观测、不确定信息及执行反馈；区分预测门会打开和工具确认开门成功。正文结尾同步交代结果传递边界，不假设世界模型统一返回结构化状态或置信度。


## 全章本节检查的统一准则

十三节检查均围绕“结果如何供 Agent 使用”，保留各节特有的问题，不重复通用免责声明，不考尚未讲解的框架 API。使用现有活动情境提出可回答的问题，检查材料、结果含义与下一步的关系。

| 节 | 检查重点 |
| --- | --- |
| 输入与理解 | 定位输入缺口，标出未读清的信息 |
| 文字理解 | 保留条件，区分备选与已定安排 |
| 文档理解 | 字段含义、页码与未提供的信息 |
| 图像理解 | 补充视觉依据，避免把未读清写成否定 |
| 音频理解 | 说话者来源与不确定语气 |
| 视频理解 | 清晰度、时间缺口与原片依据 |
| 多源信息核对 | 依据、冲突及个人状态的缺口 |
| 输出与生成 | 任务状态与实际可用成果 |
| 多模态模型 | 需要的交付物与实际能力是否匹配 |
| 嵌入与重排 | 候选缺失、原文来源与继续检索 |
| 判断与决策 | 模型判断、工具核对和执行反馈 |
| 专用模型 | 不同输出类型的用途与交接检查 |
| 世界模型 | 预测条件、不确定性与实际反馈 |

检查题不默认专用模型会返回统一格式、置信度或来源；应用需要保留和组织这些信息。每节以一个场景为主，题目控制在一至两个相互承接的问题。
