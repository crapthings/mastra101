# 第十九章写作指南：身份与权限

## 章目标

承接 18 的 HTTP 入口，以访客、成员和工作人员处理团队通知为线索，分清认证、操作权限和具体记录范围。调用方自报身份不进入可信授权，允许与拒绝均有真实 HTTP 证据。认证基础、应用权限规则与 Mastra 企业版能力分别说明。

## 节目标与段落推进

| 节 | 节目标 | 段落推进 |
| --- | --- | --- |
| 认证与授权 | 明确谁、做什么、哪份记录 | 18 已接通 → 访客/成员/工作人员 → 认证/授权 → 角色与团队约定 → 401/403/404 → 提供方 |
| 认证提供方 | 验证凭证如何得到身份 | SimpleAuth 映射 → 下载 → 三请求 → server.auth → 真实身份系统 → 生命周期 |
| 令牌与会话 | 分清携带、验证与失效 | Bearer → JWT 编码/签名 → 真实有效/过期/错误密钥测试 → Cookie/Session → 退出与撤销 |
| 身份上下文 | 从已验证字段读取身份 | 请求来源 → user → 伪造请求 → mapUserToResourceId → 业务表筛选责任 |
| 路由保护 | 覆盖业务与框架入口 | 公开/保护 → 实际四请求 → 前缀变化 → Studio 认证 → 操作权限 |
| 角色与权限 | 执行前检查业务权限 | 角色映射 → notice:publish → 403/200 → 应用表与 EE 区分 → 记录范围 |
| 数据访问范围 | 对列表、读取、写入同时限定归属 | teamId → 三入口 → 数据库查询条件 → FGA 与框架范围 → 拒绝回归样本 → 20 持续运行 |

内部目标不进入正文，段落按前一步未解决的问题推进。检查题以现有通知场景作判断，不要求背方法名。

## 实现边界

- Node.js >=24；九个源文件（六入口、三模块），六份元数据。JS/TS 与下载同步。core 1.80.0、auth 1.1.5、hono 1.7.22、libsql 1.27.1、node-server 1.19.11、hono framework 4.13.13、jsonwebtoken 9.0.3、zod 4.6.7。
- 全部原生 Mastra Auth + Hono 真正 TCP 请求；没有付费模型或外部身份服务。SimpleAuth 使用明确公开的教学令牌；JWT 密钥临时生成，不打印保存。
- JWT 只展示签名/过期的原生校验，不将示例描述成完整签发、issuer/audience、刷新与撤销系统。
- 请求上下文的 user 以认证后字段为准。测试携带成员令牌同时伪造 user/role/userId，业务仍得到成员身份；不声称所有自定义字段都被自动清除。
- mapUserToResourceId 作用于框架相关资源归属；业务通知 teamId 筛选是独立应用规则，列表/单条/发布都落实。
- 角色表演示应用 RBAC 原理，没有启用企业版 server.rbac。server.fga 概念、企业版许可与 storedResources 范围职责分别说明，不伪造 EE 集成结果。
- 404 是本例不可见记录策略；401/403 用于认证失败和操作权限不足。发布只修改进程内记录，不发通知。
- 内存 LibSQL 与通知数组退出清空。无需模型凭证；真实身份系统和公网部署不在本章执行。
